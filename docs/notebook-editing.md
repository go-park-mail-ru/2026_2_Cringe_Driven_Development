# Редактирование ipynb

Запросы идут через BFF с `X-BFF-Key` и `Authorization: Bearer <access_token>`.
Префикс — `/api/v1`. Cookie и CSRF обрабатывает BFF.

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /notebooks/{id}/content` | — | `200 {hash, cells}` |
| `POST /notebooks/{id}/content/cells` | `{kind, source, index?}` | `201 {hash, cell}` |
| `PATCH /notebooks/{id}/content/cells/{cell_id}` | `{source}` | `200 {hash, cell}` |
| `POST /notebooks/{id}/content/cells/{cell_id}/move` | `{index}` | `200 {hash}` |
| `DELETE /notebooks/{id}/content/cells/{cell_id}` | — | `200 {hash}` |

Изменяющие запросы передают `If-Match: "<hash>"`. `hash` — непрозрачный токен
редакции всего блокнота (UUID), а не SHA-256 файла. Content и ответы редактирования
возвращают его также в `ETag`. Слабые ETag, wildcard, списки и повторные заголовки
отклоняются с `400`. Две записи с одним токеном дают один успех и один
`409 notebook_conflict`. После конфликта или неоднозначной сетевой ошибки нужно
перечитать content и сверить несохранённые изменения. No-op сохраняет токен и дату.

Создавать можно `code` и `markdown`; импортированные `raw` сохраняются
и доступны для чтения и экспорта. Индексы начинаются с нуля; без `index`
вставка идёт в конец, индекс перемещения означает итоговую позицию. Последнюю
ячейку можно удалить. Старые операции `/cells` и `/cells/{index}` тоже проверяют
редакцию под блокировкой **до** выбора ячейки по индексу.

Content возвращает согласованные source, результаты и токен. У code всегда
есть `outputs` (массив, по умолчанию `[]`), `execution_count` (целое либо `null`)
и предусмотренный актуальным runtime-контрактом `output_truncated` (по умолчанию
`false`). Результаты сохраняются после завершения runtime-сессии.

## Хранение и атомарность

PostgreSQL — единственный рабочий источник ipynb. `notebooks` хранит владельца,
название, редакцию, даты, число ячеек, превью, размеры и верхнеуровневые поля.
`notebook_cells` хранит ID, позицию, source, его версию, metadata и дополнительные
поля. `notebook_cell_data` отдельно хранит outputs, execution_count, attachments
и runtime-флаг усечения. При экспорте флаг восстанавливается в owned metadata
`cellestial_runtime.output_truncated`; остальные поля namespace сохраняются.
Целая ячейка не дублируется в JSONB.

Каждая операция берёт `SELECT FOR UPDATE` строки блокнота, проверяет владельца
и редакцию, меняет нужные строки и публикует редакцию, размеры, превью и дату
одной транзакцией. Отложенная уникальность позиций допускает перестановку
диапазона без временных конфликтов. Перемещение не обновляет source или данные
ячейки. Чтение content выполняется в read-only repeatable-read снимке.

PATCH читает только целевую ячейку и числовые размеры её частей. Он не собирает
ipynb, не хеширует документ и не загружает outputs/attachments. Для превью
частичный индекс на кандидатах позволяет прочитать source одной подходящей
code-ячейки. Изменение source code-ячейки сбрасывает только её outputs,
execution_count и runtime-флаг; attachments и прочие поля сохраняются.

Внутренний порт `usecase.Results` предназначен для #13: `ExecutionSource` выдаёт
стабильный cell ID, source и его версию, а `SaveResult` принимает их идентификаторы,
outputs, execution_count и output_truncated. Результат проверяет версию source,
а не общую редакцию: правки соседей и перемещение допустимы; изменение source
(включая возврат к прежнему тексту) или удаление отвергают устаревший результат
через `ErrStaleSource`. Запись результата проверяет размер, меняет редакцию
атомарно и не затрагивает attachments. Одинаковый результат — no-op.

## Список и активная сессия

Список читает компактные метаданные, без JSONB содержимого и без S3.
`preview_code` — первые шесть строк первой code-ячейки с непробельным source,
затем первые 1024 Unicode-символа. Отступы и текст не меняются; при отсутствии
такой ячейки возвращается `""`. Поле содержит обычный текст.

`has_active_session` вычисляется одним вызовом `ActiveSessions.ActiveNotebook`
для пользователя на весь список. App подключает `runtimesession.Store`, который
читает авторитетную активную сессию #13; в изолированных тестах используется
`NoActiveSessions` или управляемое состояние. Auth-сессии,
provisioning VPS и история выполнения не являются источниками этого признака.
Ошибка подключённого сервиса не превращается в `false`.

## Формат экспорта и размеры

Максимум: 1000 ячеек, source — 65536 байт UTF-8, тело редактирования — 524288 байт,
полный экспорт — **134217728 байт**, включая все JSON-поля. Превышение даёт
`413 validation_error` для HTTP или `ErrTooLarge` внутреннему вызывающему;
транзакция откатывается целиком, включая запись runtime-результата.

Единый компактный формат использует `encoding/json`: ключи объектов сортируются,
строки экранируются его стандартными правилами (включая HTML-символы), отступов
и завершающего перевода строки нет. Source хранится и экспортируется строкой;
импортируемый массив строк склеивается без изменения текста. Числа нормализуются
в десятичную запись без экспоненты и незначащих дробных нулей, что исключает
расхождение после JSONB. Порядок ячеек сохраняется, порядок JSON-ключей и исходное
форматирование не сохраняются. Metadata, неизвестные поля и наличие необязательных
данных сохраняются. NUL, некорректный UTF-8, непарные суррогаты и неподдерживаемые
PostgreSQL числа отклоняются явно.

`header_bytes` — длина объекта верхнего уровня без `cells`. `edit_bytes` — длина
объекта лёгких полей ячейки. Размер каждой присутствующей тяжёлой части включает
запятую, JSON-ключ, двоеточие и значение. Общий размер равен:

```text
header_bytes + len(',"cells":[]')
  + sum(edit_bytes + outputs_bytes + execution_bytes + attachments_bytes + runtime_metadata_bytes)
  + max(cells_count - 1, 0)
```

`runtime_metadata_overhead` хранит постоянную стоимость JSON-обрамления флага,
`runtime_metadata_bytes` — его текущий вклад с true/false. Metadata JSONB при
сбросе или записи результата не загружается и не переписывается. При коллизии
owned namespace неизвестное значение сохраняется, а runtime-проекция отклоняется.

При изменении source дельта равна разнице длин его JSON-строк плюс дельта сброса
результата. Используются сохранённые счётчики, не размеры JSONB/TOAST.
Полная сборка допустима только при импорте, экспорте и одноразовом переносе.
