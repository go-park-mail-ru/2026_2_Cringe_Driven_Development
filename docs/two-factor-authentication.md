# Двухфакторная аутентификация

Контракт BFF → Go описан в Apidog. Все пути ниже относительно `/api/v1`;
для каждой операции нужен `X-BFF-Key`, для настройки и отключения — также
действующая Bearer-сессия текущего пользователя.

## Настройка

`POST /auth/enable2fa` без тела возвращает JSON `{qr_code, secret}` и
`Cache-Control: no-store`. `qr_code` — PNG data URI; `secret` — ключ для ручного
добавления в приложение на том же телефоне. QR и ключ задают один TOTP-аккаунт:
issuer `Cellestial`, имя — логин, SHA-1, шесть цифр, период 30 секунд.
Допускается расхождение часов на один период в каждую сторону.

До подтверждения `has_2fa=false`; повторный запрос возвращает тот же секрет,
а вход не требует второго фактора. `POST /auth/confirm2fa` с
`{"user_code":"012345"}` активирует секрет только после успешной проверки.
Код — строка из шести ASCII-цифр; ведущие нули сохраняются. Неверный формат,
отсутствие настройки или уже включённая 2FA дают 400; неверный TOTP — 401.
Активный секрет повторно не выдаётся: enable возвращает 400.

## Вход и отключение

Login сохраняет ответ `{user,tokens}`; `user` включает `has_2fa`.
Неверные credentials дают 400. При верных credentials и включённой 2FA
отсутствующее поле `user_code` даёт 412 `two_factor_required`, пустой,
неверный или уже использованный код — 401 `invalid_totp`. Полноценная сессия
создаётся только после проверки второго фактора. При выключенной 2FA
`user_code` игнорируется.

`POST /auth/disable2fa` принимает `{"password":"user-password"}`:
выключенная 2FA — 400, неверный пароль — 403, успех — 200 без тела.
Секрет удаляется; следующее подключение создаёт новый.
Включение и отключение сохраняют ранее открытые сессии.

## Хранение и ограничения

`TOTP_ENCRYPTION_KEY` обязателен для запуска: Base64 от отдельного случайного
32-байтового ключа. Генерация: `openssl rand -base64 32`. Для локального Compose
запишите значение в игнорируемый `.env`; для production передачу секрета
настраивает infra. Не используйте JWT-ключ или runtime-ключ вместо него.
Сохраните ключ отдельно от резервной копии БД: его потеря делает существующие
TOTP-секреты нечитаемыми. Прямая замена ключа без перешифрования не поддерживается.

Секрет шифруется AES-256-GCM со случайным nonce и AAD с ID пользователя.
Данные настройки, пароли и коды не журналируются. Блокировка строки пользователя
сериализует настройку, подтверждение, вход и отключение. Последний принятый
временной шаг хранится в PostgreSQL; код подтверждения нельзя сразу повторить
при входе. При запросе шага старше либо равного принятому ответ — 401.

Лимиты атомарно учитываются в общем Redis primary, отдельно по операциям:
вход — 10 запросов, подтверждение — 5, отключение — 5, получение QR — 30
за окно 60 секунд с первого запроса. Для известных пользователей ключ связан
с ID аккаунта; для неизвестного логина используется хеш логина без учёта регистра.
Получение QR не сбрасывает лимит подтверждения. Исчерпание даёт 429
`rate_limited`; недоступность Redis не разрешает проверку пароля/TOTP.

## Проверки

Контракт 2FA принят в Apidog `main`. Пока контракт №65 ещё находится в ветке
`api-65` (`1421677`), совместная генерация выполняется командой
`make APIDOG_BRANCH_ID=1421677 generate`: ветка наследует 2FA из `main`.
После слияния контракта №65 перед PR необходимо выполнить
`make APIDOG_BRANCH_ID= generate`, чтобы итоговый код был сгенерирован из `main`.

`make check` выполняет unit-тесты, race и lint. Интеграционные проверки требуют
изолированных PostgreSQL и Redis; тесты создают собственные схему и префикс:

```sh
TEST_POSTGRES_DSN='postgres://.../test?sslmode=disable' \
REDIS_TEST_ADDR=127.0.0.1:6379 REDIS_TEST_PASSWORD='...' \
go test -race ./internal/user/... ./internal/transport/http/... -count=1
```

Тесты проверяют RFC-векторы и ведущие нули, декодирование QR, шифрование,
конкурентные setup/confirm/login, replay, отсутствие сессии при отказе,
отключение, сохранение сессий, лимиты и отсутствие секретов в логах.
Совместно с frontend#47 дополнительно проверяют ручное добавление ключа
на одном телефоне и подключение через QR в настоящем приложении-аутентификаторе.
