# Доступ к блокнотам и клонирование

Контракт Go API находится в `spec/openapi.json`, пути ниже — относительно `/api/v1`. Для всех запросов обязателен `X-BFF-Key`. Браузер вызывает BFF, а не Go API напрямую.

## Режимы и операции

Новый блокнот и любая копия имеют режим `private`. В `restricted` читают владелец и адресные получатели, в `public` — все посетители, включая анонимов. Редактирование документа, удаление и управление runtime остаются только у владельца. Список `GET /notebooks` по-прежнему содержит только собственные блокноты.

Владелец получает настройки через `GET /notebooks/{id}/sharing`:

```json
{"mode":"restricted","readers":[{"id":2,"login":"reader"}]}
```

`PUT /notebooks/{id}/sharing` целиком заменяет настройки:

```json
{"mode":"restricted","reader_logins":["reader"]}
```

Для `private` и `public` передавайте пустой `reader_logins`. Эти режимы удаляют адресные разрешения. Возврат к restricted требует передать получателей заново; пустой restricted допускается. Неизвестный логин или невалидные настройки дают 400 без частичного изменения. Регистр логина несущественен, повторы сворачиваются, владелец исключается. Разрешения ссылаются на ID пользователя; смена логина их не отменяет. Список получателей доступен только владельцу.

`GET /users/suggest?q=rea&limit=10` возвращает только `{items:[{id,login}]}`. Требуется сессия; поиск по ASCII-префиксу после обрезки пробелов (1–32 буквы, цифры или `_`), без учёта регистра. `_` буквальный. limit — 1–20, по умолчанию 10. Текущий пользователь исключён. Общий Redis-бюджет — 60 запросов за 60 секунд на пользователя, превышение — 429 `rate_limited`. Ошибка Redis не разрешает запрос.

## Чтение и BFF

Только `GET /notebooks/{id}` и `GET /notebooks/{id}/content` допускают отсутствие Bearer. Переданный неверный/истёкший/отозванный Bearer возвращает 401, а не превращается в анонимный запрос. Закрытый, удалённый и отсутствующий блокнот возвращают одинаковый 404. Метаданные и content проверяют права самостоятельно. Их ответы и ответы sharing используют `Cache-Control: no-store`, включая отказы до delivery.

Метаданные содержат `access`:

| Посетитель | is_owner | can_edit | can_manage_sharing | can_clone |
|---|---|---|---|---|
| Владелец | true | true | true | true |
| Авторизованный читатель | false | false | false | true |
| Аноним | false | false | false | false |

Сохранённые результаты выдаются существующим content API, ETag/hash сохраняется. Полный список читателей и приватное состояние runtime в ответы чтения не добавляются. Для новых usecase доступен `NotebookUsecase.CheckRead(ctx, id, userID)`; ID 0 обозначает анонимного посетителя. Проверка чтения не заменяет проверки авторства и модерации комментариев.

## Копия

`POST /notebooks/{id}/clone` с телом `{"name":"Моя копия"}` требует сессию и право чтения исходника. Владелец также может копировать свой блокнот. Имя обрезается по краям и должно содержать 1–128 Unicode-символов; одинаковые имена разрешены. Ответ — 201 с новым Notebook.

Копия имеет нового владельца, ID, даты, ревизию и source_version ячеек. ID ячеек уникальны в пределах блокнота и могут сохраняться. Копируется полный документ: metadata/extra, исходники, порядок и типы ячеек, attachments, outputs, execution_count и признак усечения. Runtime, задания, workspace, комментарии и разрешения не копируются. Ошибка записи откатывает весь новый документ. Копия не зависит от дальнейшей судьбы исходника.

PUT, clone, edit, сохранение результата и delete используют общую блокировку строки исходного блокнота. Clone проверяет права после захвата блокировки отдельным запросом, поэтому завершившийся отзыв доступа учитывается и после ожидания. Чтение content использует repeatable-read снимок.

## Передача frontend#260

Использовать SHA коммита backend, содержащего обновлённый `spec/openapi.json`; SHA назначается после коммита. Новые operationId: `getNotebookSharing`, `putNotebookSharing`, `cloneNotebook`, `suggestUsers`.

В BFF нужно обновить сгенерированный Go-клиент, гостевые notebooks.get/content, HTML bootstrap, tRPC и загрузчик страницы. При отсутствии сессии не отправлять Bearer и не запрашивать приватный runtime. Режим интерфейса и доступные действия определять по `access`. Не считать отсутствие runtime ошибкой гостевой страницы. Подключить подсказки, замену настроек и диалог имени копии.

Совместная приёмка после подключения frontend: анонимное открытие public по прямой ссылке и SPA-переходу; restricted после входа адресата; 404 на новых запросах после отзыва; независимое редактирование/запуск копии. Backend-тесты не подтверждают готовность этих пользовательских сценариев BFF.
