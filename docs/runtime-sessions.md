# Пользовательские runtime-сессии

Модуль `internal/runtimesession` связывает пользователя, блокнот и окружение #57.
Одна незавершённая сессия занимает слот пользователя во всех его блокнотах.
Сессия и окружение используют один UUID. Языки — `python` и `r`, профиль — `default`.

## API

Источник контракта — Apidog; HTTP доступен только через BFF. Требуются
`X-BFF-Key` и Bearer access JWT, проверяемый через Redis. Токен/URL агента,
приватный IP и облачные идентификаторы клиенту не передаются.
Все пути ниже относительно `/api/v1`:

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/notebooks/{id}/runtime-sessions` | 202, сохранённая сессия; подготовка асинхронна |
| GET | `/runtime-sessions/active` | `active_session`: сессия или `null` |
| GET | `/runtime-sessions/{id}` | состояние и этап |
| POST | `/runtime-sessions/{id}/executions` | 202, исполнение сохранённой ячейки |
| GET | `/runtime-sessions/{id}/executions/{execution_id}` | состояние и накопленный вывод |
| GET | `/runtime-sessions/{id}/events?after=0` | события, `next_cursor`, `has_more` |
| POST | `/runtime-sessions/{id}/activity` | уведомление о действиях в редакторе |
| POST | `/runtime-sessions/{id}/stop` | 202, намерение остановки |
| POST | `/runtime-sessions/{id}/executions/batch` | атомарный Run all, request_id и полный execution_ids |
| GET | `/runtime-sessions/{id}/queue` | RUNNING/QUEUED code-ячеек; инспекции не включены |
| POST | `/runtime-sessions/{id}/variables` | 202, инспекция в общей durable FIFO |
| GET | `/runtime-sessions/{id}/variables/{execution_id}` | сохранённые состояние и дескрипторы переменных |
| POST | `/runtime-sessions/{id}/kernel/interrupt` | запрос прерывания, итог читается отдельно |
| POST | `/runtime-sessions/{id}/kernel/restart` | новое поколение только при полностью свободном kernel |

Start принимает `request_id` и язык. Повтор того же запроса возвращает ту же
сессию; несовместимый повтор — 409 `conflict`. При другом запуске с занятым
слотом — 409 `active_session_exists` и публичная `active_session`, включая
`notebook_id`. Чужие сессии и блокноты возвращают 404.

Execute принимает `execution_id`, `cell_id`, `source_hash` (SHA-256 сохранённого
UTF-8 source), `timeout_seconds` (1–86400, по умолчанию 300). Текст программы
берётся из сохранённой ячейки PostgreSQL под блокировкой строки блокнота, не из тела команды.
Повтор ID не запускает другую попытку; несовпадающие параметры дают 409.

## Владение и восстановление

`internal/runtime` управляет OpenStack/Ansible, сетью и секретами; только его
воркер удаляет ресурсы. SessionAgent из общей сборки использует уже выданный
токен и тот же mTLS-клиент. Второго provisioning-пути нет.

Сессии, неизменяемые команды, публичные события и задания проекции хранятся
в четырёх таблицах новой миграции. Создание/команда/activity/остановка сохраняются
до внешних вызовов. Lease и версия не разрешают старому воркеру перезаписать
новое намерение пользователя. Неопределённый ответ повторяется с прежним ID.

Состояния: PROVISIONING → STARTING → READY; при потере связи RECONNECTING;
при завершении STOPPING → STOPPED/FAILED. Состояние исполнения ячейки хранится
отдельно. STOPPING удерживает пользовательский слот до остановки агента и архивации.
После этого STOPPED/FAILED освобождает слот; cleanup_pending независимо показывает,
что удаление облачных ресурсов ещё не подтверждено. Фоновый обработчик продолжает
очистку таких завершённых сессий и после перезапуска backend.

Агент определяет простой: 15 минут без команд/activity, когда нет исполнения
и очереди. Go обнаруживает остановку, архивирует журнал и запрашивает удаление.
Редактор должен отправлять activity по реальным действиям, не чаще раза в
30 секунд. Чтение output и открытая вкладка не продлевают простой.
Go опрашивает агент примерно раз в 2 секунды; reconnect — 1/2/4/8/16 секунд.
Один HTTP-вызов ограничен 5 секундами, redirects запрещены.

Перед удалением: drain → stop → доступный журнал → транзакционный архив
PostgreSQL → checkpoint → RequestDelete. Ошибка БД не подтверждает архивацию.
После шести сетевых отказов журнала допускается неполная архивация и удаление;
`journal_incomplete=true`, незавершённые исполнения получают UNKNOWN. Неполный
результат не объявляется успешным. Временный сбой БД оставляет проекцию на повтор,
но не удерживает VPS после сохранения архива в БД.

События дедуплицируются по agent seq; публичный cursor независим от agent seq.
Страница ограничена 100 событиями и целевыми 16 MiB; первое крупное событие
возвращается целиком. HTTP body агента ограничен 64 MiB. Heartbeat не сохраняется.

## Вывод и редакции ipynb

Reducer сохраняет stream, MIME display, error, clear_output, display_id update,
execution_count и признак усечения вывода. Вывод не исполняется сервером.
Frontend должен безопасно отображать недоверенный HTML/SVG.

Проекция выполняется под той же notebook row lock, что редактирование ячеек.
В одной транзакции PostgreSQL меняются outputs/count/truncated нужной ячейки,
редакция и размер блокнота, подтверждение проекции. При приёме команды фиксируются
source и его версия; при публикации проверяются эта версия и последняя попытка
ячейки. Перемещение и изменения соседей не мешают результату, изменение source,
включая возврат к прежнему тексту, и удаление дают projection=conflict.
Неподдерживаемые JSONB значения (NUL) и превышение 128 МиБ также не публикуются:
проекция получает conflict, исходный результат сохраняется в архиве исполнения.
Metadata, attachments и неизвестные поля ipynb сохраняются; transient display_id
не попадает в nbformat outputs. S3 в этом пути не используется.

## Запуск и проверки

Настройки provisioning и fake/real — [runtime-provisioning.md](runtime-provisioning.md).
Новые облачные credentials не требуются. При `RUNTIME_ENABLED=false` новые
сессии запрещены; история читается, stop сохраняется для восстановления.
Сервис сессий и provisioning завершают фоновые задания до закрытия пула БД.
Выход пользователя из авторизации сам по себе не удаляет его VPS.

Для интеграционных тестов используются отдельные PostgreSQL и Redis:

```sh
RUNTIME_TEST_DATABASE_URL=postgres://... \
REDIS_TEST_ADDR=127.0.0.1:6379 \
go test -race ./internal/app ./internal/runtimesession/... -count=1
```

Тест создаёт собственные схему PostgreSQL и Redis prefix. Проверяется
HTTP/BFF/JWT → сессия → fake provisioning/agent → события → ячейки PostgreSQL → cleanup,
включая конфликт второй сессии и отзыв доступа через logout-all.
Fake не подтверждает работоспособность Selectel или настоящего Python.
Реальный smoke проводят на согласованном стенде по runtime-provisioning.md;
он должен дополнительно проверить пользовательский API и вывод в ipynb.

## Очередь, пакет и память kernel

Run all принимает фиксированный упорядоченный набор cell_id/source_hash. Backend сохраняет
все исходники и IDs одной транзакцией; позднее добавленные ячейки не включаются.
Повтор request_id возвращает тот же полный список IDs, даже после завершения пакета.
Недостаточная ёмкость/конфликт не оставляют частично принятых команд. Общая ёмкость
незавершённых команд — 1000; переполненный агент временно задерживает dispatch, не
превращает принятые backend команды в потерянные исполнения.

Инспекция имеет execution_id в общем пространстве команд, но не является ячейкой.
В публичных событиях ей соответствует inspection_id без execution_id; результат
читается через variables. В queue только code-команды. Поэтому пустая queue не
заменяет серверную проверку отсутствия инспекций перед restart. Инспекция ограничена
5 секундами выполнения и 200 дескрипторами. Значения preview — недоверенный текст.
Управляющие interrupt/restart автоматически не повторяются при потере ответа.

## Сохранённые результаты и редакция

GET content возвращает code-ячейки с outputs, execution_count и output_truncated,
в том числе без активной сессии. Для отсутствующего результата — []/null/false.
Флаг усечения относится к сохранённому результату и заменяется новым результатом.
Редакция для If-Match — непрозрачный токен всего документа: меняется при изменении
source, порядка и результатов. source_hash исполнения остаётся отдельным SHA-256
исходника конкретной ячейки для HTTP-контракта; внутренняя версия source дополнительно
защищает публикацию от ABA. Полное хранение и размеры —
[notebook-editing.md](notebook-editing.md); вместо переноса — [сброс БД](database-reset.md).
Агент и EnvironmentService не обращаются к S3/PostgreSQL и не требуют изменений
для хранения по ячейкам.

## Локальная проверка с настоящим агентом

К переменным интеграционного окружения выше добавьте `RUNTIME_TEST_REAL_AGENT=1`.
Требуются runtime-agent/.venv, Docker и готовый образ kernel Python (`make agent-images`).
Тест создаёт отдельную Docker-сеть, запускает Python-агента для каждой сессии,
использует loopback mTLS relay и существующий защищённый Go-клиент. PostgreSQL,
Redis настоящие; только выделение/удаление VPS остаётся fake. Проверяются
обе языковые сессии, очередь, batch, переменные, управление kernel и сохранение
результатов в ipynb после остановки. Это локальный protocol test, не проверка
сетевой изоляции production или доступности Selectel.

Выводы и произвольные результаты исполнения сохраняются в JSONB как base64 JSON-байты,
исходный код сохраняется как base64. Тела событий хранятся в bytea. Это обратимые
внутренние представления: HTTP и ipynb получают исходные данные, включая NUL.
Следующая команда выбирается отдельно от завершённой истории. События обновляют
только связанные исполнения; display_id индексируется по хэшу и обходится страницами.
